# aylayoo — багт зориулсан тайлбар

Шинэчилсэн: 2026-11-10. Энэ репо **нийтийн** — нэвтрэх нэр, нууц үг, хөтөчийн хувийн дугаар,
имэйл зэргийг **хэзээ ч** нэмэхгүй. Техникийн дэлгэрэнгүйг [`STATUS.md`](./STATUS.md)-аас.

## Юу хийгдсэн бэ

**1-р шат — нийтийн сайт. Ажиллаж байна** (https://aylayoo.com): нүүр хуудас, 22 аймаг,
газрууд, хөтөч нар, дэлгэрэнгүй хуудсууд, SEO, sitemap.

**2-р шат — Улаанбаатар хэсэг (`/ulaanbaatar`). Ажиллаж байна:** аяллын хөтөлбөр, явган
маршрут, хоолны газар, хэрэгтэй мэдээлэл, монгол хэллэг, арга хэмжээ — бүгдийг `/admin`-аас
нийтэлдэг. **Хоол, арга хэмжээ зориуд хоосон:** бодит газар, үнийг зохиож бичихгүй.

**3-р шат — хөтөчтэй аялал, аяллын хүсэлт (R1a). Ажиллаж байна** (2026-11-06-наас): аяллын
хуудас, хүсэлтийн форм, `/admin` дээрх дамжуулах хэсэг. Нүүрээс **"Хөтөчтэй аялал"** товчоор
орно. **Хоосон байгаа нь алдаа биш** — зөвшөөрөл, нийтэлсэн аялал хоёулаа байхгүй учраас.

**R1b — "Миний төлөвлөгөө". Бэлэн, гэхдээ ажиллуулаагүй.** Таалагдсан газар, аялал,
хөтөлбөрөө нэг жагсаалт болгон хадгалж холбоосоор хуваалцдаг; бүртгэл шаардахгүй. Код бэлэн,
тест хийгдсэн ч өөр салбарт байгаа тул **энэ репод ч, сайт дээр ч байхгүй**.

## Кодыг татаж ажиллуулах

```bash
git clone https://github.com/Aylay-oo/aylayoo.git
cd aylayoo && bun install
git pull origin main                      # дараа нь шинэчлэхдээ
cd aylayoo-service && bunx wrangler dev   # API, 4003 порт (1-р терминал)
cd aylayoo-web && bun run dev             # сайт, 3000 порт (2-р терминал)
```

**3000 портыг солихгүй** — өөр порт дээр API бүх хүсэлтийг хориглож, сайт хоосон харагдана.

**`.env` файлын нэр:** `.env.example`-ийг хуулбал нэрийг **`.env.development.local`** гэж
өгнө. **`.env.local` гэж нэрлэвэл болохгүй** — тэр нэр бүх тохиолдолд уншигддаг тул нэг удаа
нийтийн сайт дээр `localhost:4003` хаягтай код тавигдаж, бүх мэдээлэл хоосон харагдсан.

## `/admin` — зөвшөөрөл ба нийтлэх

Нэвтрэх мэдээллийг багийн ахлагчаас аваарай; энэ файлд бичихгүй. `/admin` нүүр хуудаснаас
зориуд холбоогүй, хайлтын системд ч орохгүй. Хоёр гол ажил:

**1. Хөтөчийн зөвшөөрөл** — хөтөч бүрээр, төрлөөр нь (`tours` — нийтлэх, `requests` — хүсэлт
авах). Хөтөч өөрөө зөвшөөрснийг **баталгаажуулж байж** бүртгэнэ, яаж зөвшөөрснийг нэг
өгүүлбэрээр бичнэ. Зөвшөөрлийг хүчингүй болговол түүний аяллууд автоматаар хасагдана.

**2. Аялал нийтлэх** — зөвшөөрөлгүй хөтөчийн аялалд **Нийтлэх товч ажиллахгүй**, шалтгааныг
тэндээ харуулдаг. Эхлээд зөвшөөрөл, дараа нь нийтлэх.

## Багийн хийх ажлууд

1. **Нэг хөтөчөөс зөвшөөрөл авч, аяллыг нийтлэх** — хамгийн гол ажил; үүнийг хийтэл хөтөчтэй
   аяллын хэсэг хоосон хэвээр.
2. **50 хөтөчид аймаг хуваарилах** (`/admin` → батлагдсан хөтөч нар) — одоо аймгаар шүүх
   боломжгүй.
3. **Хоол, арга хэмжээ нэмэх** — зөвхөн өөрсдөө шалгасан бодит мэдээлэл.
4. **Сайтыг утсан дээр шалгах:** нүүр, Улаанбаатар хэсэг, хөтөчтэй аялал.
5. **Имэйл, SMS-ийн шийдлийг тодруулах** — дараагийн шат (R2) үүнээс хамаарна.
